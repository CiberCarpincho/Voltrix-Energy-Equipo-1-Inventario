# HU-04 · Desplegar Inventario en EC2

El despliegue construye la imagen Go del repositorio y la ejecuta junto a PostgreSQL 16. La consulta de ejemplo lee el activo del contrato aprobado. La carga del catálogo completo y las consultas sobre esos datos corresponden a HU-03. El endpoint de salud sí verifica una conexión real a PostgreSQL en cada petición.

## Antes de crear recursos

En AWS Billing, revisa el plan, el saldo o vigencia de los beneficios y la fecha de creación de la cuenta (puedes contrastarla con el correo de bienvenida). Registra fecha, plan, región y tipo elegido para la sustentación. En EC2 verifica que el tipo x86 de 1 GiB sea elegible en esa cuenta y región. La elegibilidad depende de la cuenta y los recursos pueden generar cargos. Consulta la [documentación de EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-free-tier-usage.html).

## Desplegar desde CloudFormation

1. Publica la revisión que contiene esta HU en el repositorio del equipo. Copia su SHA completo con `git rev-parse HEAD`.
2. En la región elegida abre CloudFormation, crea una pila estándar y carga `infra/ec2/inventario.yaml`. Usa el nombre `voltrix-inventario`.
3. Selecciona la VPC y una subred pública de esa VPC con ruta a Internet Gateway. En `ApiClientCidr` escribe la IP pública de salida del cliente de prueba con máscara /32, o el CIDR acordado por el equipo. Para probar desde otro origen debe estar permitido por el grupo de seguridad.
4. Elige el tipo de instancia validado e introduce el SHA publicado. Revisa y crea la pila. El arranque configura swap de 1 GiB, instala Docker, genera la contraseña en la instancia y construye el proyecto. La única regla de entrada es TCP 8080. PostgreSQL está en la red de Compose y usa un volumen con nombre.
5. En **Outputs** copia `ApiUrl`. La creación del recurso EC2 puede terminar antes que la compilación. Usa la prueba externa para confirmar que el servicio está listo. En EC2 → Monitor and troubleshoot → Get system log se puede consultar la salida del arranque, incluido el estado de contenedores, swap y memoria.

## Probar desde PowerShell fuera de EC2

Sustituye la URL por la salida de tu pila. Guarda los resultados junto con fecha y región.

```powershell
$base = 'http://IP-PUBLICA:8080'
$salud = Invoke-RestMethod "$base/health" -TimeoutSec 10
$salud
if ($salud.estado -ne 'disponible' -or $salud.baseDatos -ne 'ok') { throw 'Falló salud' }

$activo = Invoke-RestMethod "$base/activos/PL-001-PS-07" -TimeoutSec 10
$activo
if ($activo.id -ne 'PL-001-PS-07' -or $activo.plantaId -ne 'PL-001') { throw 'Activo inesperado' }

Test-NetConnection ([uri]$base).Host -Port 5432 -InformationLevel Quiet
```

Se espera salud disponible, el panel solar de PL-001 y `False` en 5432. Captura también el grupo de seguridad y el registro de arranque con `docker compose ps`, `docker stats` y `swapon --show`. La contraseña se guarda en la instancia en `/opt/voltrix/deploy/compose/.env`. El volumen conserva los datos al recrear contenedores dentro de la misma instancia; eliminar la pila puede eliminar sus datos.

## Probar Compose en Windows antes del despliegue

Desde la raíz del repositorio, con Docker Desktop en modo Linux:

```powershell
cd deploy/compose
$env:POSTGRES_PASSWORD = [guid]::NewGuid().ToString('N')
docker compose up -d --build --wait
docker compose ps
Invoke-RestMethod http://localhost:8080/health
Invoke-RestMethod http://localhost:8080/activos/PL-001-PS-07
docker compose stop db
curl.exe -i http://localhost:8080/health
docker compose start db
```

Con la base detenida se espera HTTP 503. Al volver a iniciarla, la misma API debe recuperar HTTP 200. Conserva la contraseña mientras uses el volumen local; para sesiones posteriores puedes guardarla en `deploy/compose/.env`, archivo excluido de Git. Si el volumen ya estaba inicializado, usa su contraseña original.
